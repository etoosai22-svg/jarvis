# JARVIS Project — Part 19. Security Guide

## 보안 원칙
최소 권한 / Zero Trust / 기본 암호화 / 사용자 승인 우선 / 감사 가능성

## 0. 검증 가능한 불변식

원칙은 방향을 주지만, 아래 불변식은 **코드가 위반했는지 판정할 수 있는 규칙**이다.
위반은 버그이며, 각 항목은 테스트로 존재해야 한다 (Part 18 §1).

| # | 불변식 | 상태 |
|---|---|---|
| S1 | `user_id`는 항상 검증된 토큰의 `sub`에서만 온다. 본문·쿼리의 `user_id`는 무시된다 | ✅ 구현 + 테스트 |
| S2 | 타인 리소스 접근은 404 — 존재 여부를 노출하지 않는다 | ✅ 구현 |
| S3 | `AUTH_REQUIRED=true`에서 무토큰/위조 토큰 → 401, 예외는 `/health`뿐 | ✅ 구현 + 테스트 |
| S4 | JWT는 JWKS 서명 검증 + `exp`·`sub` 필수 + `iss`/`aud` 일치. 대칭키(HS256) 금지 | ✅ 구현 |
| S5 | 비밀키는 `.env`/Secret Manager에만 — git 추적 금지 (`.gitignore`에 `.env`) | ✅ 적용 |
| S6 | LLM API 키는 서버에서만 사용 — 앱 번들에 절대 포함 금지 (`EXPO_PUBLIC_*`에 키 넣지 않기) | ✅ 적용 |
| S7 | 토큰·API 키·메시지 원문을 로그에 출력하지 않는다 | ⚠️ 규칙만 — 검사 없음 |
| S8 | 민감 작업(메일 전송·예약 확정·결제·파일 삭제)은 실행 전 사용자 승인 필수 (Part 12 §7) | ✅ calendar 변이 도구에 적용 + 앱 승인 카드 실동작 확인 |
| S9 | 모든 MCP 도구 호출은 audit_logs에 기록 (민감값 마스킹). **실행되지 않은 결정(승인 요청·거절)도 남긴다** | ✅ 구현 + 테스트 |

## 인증 (Phase 7 목표)
OAuth 2.0 / OpenID Connect / Access Token 단기 사용 / Refresh Token 안전 저장 / MFA 지원

**현재 구현:** JWKS 기반 Bearer JWT 검증(`app/core/security.py`)까지.
IdP 선정, 토큰 발급/갱신 플로우, 앱 로그인 화면은 미착수.
`AUTH_REQUIRED=false`는 **로컬 개발 전용** — 운영 배포 체크리스트에서 true 강제.

## 권한 관리
사용자별 데이터 격리(S1·S2) / RBAC(다중 사용자 도입 시) / 민감 작업 재인증(S8)

## 데이터 보호
TLS 통신(운영 리버스프록시에서 종료) / 저장 데이터 암호화 / 비밀번호 저장 금지 / API 키는 서버에서만(S6)

## 비밀키 관리
Secret Manager 사용(운영) / Git 저장 금지(S5) / 로그 출력 금지(S7) / 주기적 Rotation

## 개인정보
최소 수집 / 삭제 요청 지원 / 기억 수정·삭제 기능(→ memory DELETE API가 계약에 추가되어야 함, Part 9 §4) / 민감 정보 명시적 동의 후 저장

## 감사 로그
`audit_logs` 테이블은 존재(Part 13). 기록 주체는 MCP Gateway(S9) — 현재 기록 코드는 없다.
기록 필드: 사용자 / 요청 ID / 작업 / 결과 / 시간 / 승인 여부 (민감 정보 마스킹)

## 외부 서비스 (Phase 5~)
OAuth 기반 연동 / 권한 범위 최소화 / 토큰 만료 감지 / 연결 해제 지원

## 사고 대응
비밀키 폐기 / 세션 무효화 / 로그 분석 / 사용자 알림 / 복구 절차

## MVP 완료 기준 (판정 가능형)
- [ ] 운영 엔드포인트가 HTTPS로만 노출된다
- [x] S1~S4 불변식이 테스트로 보장된다 (S2의 교차 사용자 케이스는 OAuth 후)
- [x] 저장소에 비밀키가 없다 (`git log -p | grep` 검사 통과)
- [ ] OAuth 로그인으로 실사용자 토큰이 발급된다
- [x] 민감 작업 승인 플로우가 동작한다 (S8) — 앱 승인 버튼 → 백엔드 실행까지 실측
- [x] audit_logs에 도구 호출이 기록된다 (S9) — 승인 요청·성공·거절 3종 모두
